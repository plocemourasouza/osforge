Seeded defect (ground truth, 1 primary):
D1. Data loss: `split_part(full_name, ' ', 2)` keeps only the second word, so every name with three or more words (e.g. "Maria da Silva Santos" -> last_name "da") silently loses the rest, and `full_name` is then dropped in the same migration, making the loss unrecoverable. Fix: last_name = everything after the first space (e.g. substring/regexp), keep full_name until verified, drop in a later migration.
Secondary legitimate issues (real, not manufactured if raised): dropping full_name in the same release as the app switch breaks rollback / old app instances still reading full_name during deploy; NULL or single-word full_name gives empty-string last_name and NULL full_name would make first_name NULL -> SET NOT NULL fails; a single 4M-row UPDATE in one transaction holds locks long.
